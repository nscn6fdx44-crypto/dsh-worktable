# v0.10.3 — 克隆仓库可以浏览目录了

> 2026-10-19 · 增量版本 · 自测 host **171** + client **572** 全通过

## 一句话

克隆弹窗的「克隆到」右边多了个「浏览…」：在磁盘上逐级点，选到哪就填到哪，
不用再自己把路径敲全。

## 加了什么

「克隆到」那一行：输入框 + 「浏览…」。点开后是一个内嵌的目录面板：

| 元素 | 作用 |
|---|---|
| 顶部路径 | 当前所在目录（太长会省略中间，悬停看全路径） |
| `↑` | 上一级；已经在盘符根就置灰 |
| `↻` | 重新列一遍 |
| `✕` | 收起面板（输入框里的值不动） |
| 文件夹行 | 点一下进这一级 |
| 「用这个目录」 | 把当前目录回填到「克隆到」，面板收起 |

默认从「克隆到」当前的路径开始；那一格是空的就退回工作目录。
手打路径的方式完全保留 —— 想换盘（`C:` → `D:`）最快还是直接改输入框再点「浏览」。

## 为什么不用系统选择框

浏览器里 `<input type="file" webkitdirectory>` 只给**文件名**，不给绝对路径。
克隆需要的是一个能落盘的绝对路径，所以这条路走不通，只能靠 `/fs/list` 自己画一棵树。

## 一个容易踩的坑：能翻到 ≠ 能写

`/fs/list` 的读权限**不设白名单**（文件管理器要能一路翻到盘符根），但克隆属于写操作，
必须落在白名单根内 —— 进程 cwd、用户 home、`DSH_HOME`、已注册的项目根。

于是存在这种情况：`D:\` 能翻、`D:\projects` 能翻，但克隆到那里会被拒。如果只在点「克隆」
的时候才报，用户会白填一堆东西。

所以浏览时把 `/fs/list` 返回的 `writable` 直接判断掉：

- 可写 → 正常，底部提示「会用这个目录当仓库的上级目录」
- 不可写 → 当场亮红「这个位置不在可写白名单内」，并且**禁用**「用这个目录」

## 实现

| 层 | 做法 |
|---|---|
| 数据 | 复用 `POST /fs/list`，没有新增后端接口；一次只列一层，进目录再发一次 |
| 过滤 | 只留 `dir === true` 的条目（`dirOnly`），文件不占位置 |
| 视图 | `DirView` 是纯展示组件（数据全从 props 来），容器 `DirBrowse` 只管取数和状态 |
| 上限 | 最多画 300 行 —— 一个塞了几千个子目录的文件夹不至于把弹窗撑爆 |

`DirView` 单拎出来是为了能离线自测：弹窗内部状态在测试桩里不会重渲染，
纯展示组件可以带着不同 props 直接渲染，把「可写/不可写/空目录/列失败/到根」五种形态
和两个按钮的回调都断言掉。
