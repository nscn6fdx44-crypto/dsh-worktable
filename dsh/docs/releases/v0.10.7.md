# v0.10.7 — 把 `.html` 拖进窗格，不再被那层遮罩卡住

## 现象

整个 DSH 窗口被一层灰底盖住，中间写着「文件或图片拖动到此处即可添加 / 图片限制：最多 20 张，每张 20MB」。
**没有按钮、点不掉、`Esc` 也没用**，只能杀进程或托盘退出重开。

## 真正的原因

不是弹窗。读宿主的 `app.asar` 才看清（`@deepseek-ai/dsh-client-ui-attachment` 包）：

- `drop-events.js` 的 `installDocumentDropEvents()` 在 **`document` 上**挂了 `dragenter` / `dragover` /
  `dragleave` / `drop` 四个监听，**没传 capture**（即冒泡阶段），只认 `dataTransfer.types` 里的 `Files`；
- 命中就 `setDragActive(true)`，`ComposerAttachments` 随即渲染 `<DropOverlay>` —— portal 到 `document.body`，
  `position: fixed; inset: 0`，并且 **`pointer-events: none`**（宿主源码注释自己写明 "Decoration only"）；
- 这层遮罩只有两条关闭路径：宿主自己的 `onDrop` 里 `reset()`（`dragDepth = 0` + `setDragActive(false)`），
  以及 `window` 上的 `dragend`。而「从资源管理器拖进来」的拖拽**不会**在页面里派发 `dragend`。

于是：0.10.6 的窗格没有 `drop` 处理器 → 事件冒到宿主 → 宿主接走并加了附件；0.10.7 第一版给窗格加上
`drop` 处理器并 `stopPropagation()` → 宿主的 `onDrop` **跑不到了**，`reset()` 永不执行 →
`dragActive` 永远是 `true`，遮罩永远挂在屏幕上。

因为它 `pointer-events: none`，既不挡点击也不挡 drop，所以**文件其实已经放进去了**，卡住的只是那层灰底 ——
这也是「点不掉、Esc 也没用」的原因：它压根没有交互层。

前两轮都判错了方向：第一轮以为宿主弹的是带按钮的确认框（宿主没有这种框），第二轮怀疑 iframe 里的
`alert` 被 `allow-modals` 放行（顺手修了，是另一件事，不是元凶）。

## 怎么修的

`core.js` 里加三个纯函数 + 一个安装器：

- `isFileDragEvent(e)` —— 判断这次拖的是不是系统文件（`Files` / `text/uri-list` / 本插件自己的
  `application/x-wt-file`），拖标签页和拖会话行不算。
- `pointsIntoWorkbench(e)` —— 用 `document.elementFromPoint()` 判断指针在不在 `.wt-scope` 里。
  遮罩是 `pointer-events:none`，`elementFromPoint` 会自动跳过它，所以量到的是遮罩底下真实的元素。
- `resetHostDropMask()` —— 合成一发 `dragleave` 打在 `document.documentElement` 上：`clientX/clientY = -1`、
  `dataTransfer.types` 带 `Files` 但 `files` 是空数组。宿主走「指针离开视口」那条分支，把 `dragDepth`
  清零并 `setDragActive(false)`；因为文件列表是空的，它什么都不会往对话里加。
- `installDropMaskGuard()` —— 在 **`document` 捕获阶段**拦 `dragenter`（比宿主的冒泡监听早，也比 React
  根容器早）：指针在工作台上就 `stopPropagation()`，宿主进不了 `dragActive`，遮罩压根不出现；顺手再补发
  一发 `resetHostDropMask()`，把「先落在宿主区域、再移进工作台」时已经亮起来的那层也关掉。

接线：

- `panes.js` 自定义窗格 `onDrop`、`overlay.js` 的 `swallowOsDrop()` 处理完之后都补发一次
  `resetHostDropMask()` 兜底；
- 客户端入口 `apply()` 里 `ctx.effect(() => installDropMaskGuard(), …)`，插件 dispose 时自动摘掉。

## 要点

- 遮罩不挡事件，只挡视线：问题从来不是「放不进去」，而是「放进去之后那层灰底下不去」。
- 只 `stopPropagation` 不够：宿主的监听在 `document` 冒泡阶段，我们的 `drop` 处理器也在冒泡链上 ——
  掐掉它的同时，必须替它把 `dragActive` 收拾干净。

## 测试

- host **188 → 189**（`/asset` 的响应头与 iframe 的 sandbox 都不再带 `allow-modals`）；
- client **585 → 616**（+31）：`.html` 拖进窗格落成 `kind:'file'` 草稿（含文件名顶名、直接进预览）、
  非网页文件拦下且不改草稿、拖标签页不抢事件、`.pane-main` 兜底、预览沙箱不含 `allow-same-origin`，
  以及本版新增的宿主遮罩守卫 ——
  `isFileDragEvent` 的四种形态、`pointsIntoWorkbench` 的两个方向、`resetHostDropMask` 合成事件的确切形状
  （`dragleave` / 坐标为负 / `Files` 但空文件）、守卫挂在捕获阶段、命中工作台掐断 / 宿主区域放行 /
  拖自己的标签页不掐、`off()` 能摘掉监听。

## 怎么验

**纯客户端改动，不用重启 DSH**：刷新工作台页面即可。

1. 从资源管理器把 `.html` 拖到「自定义」窗格 → 全程**不该出现**那层灰底「文件或图片拖动到此处即可添加」，
   只有窗格自己的虚线高亮 +「松手 → 放进这个窗格」；松手后直接出预览。
2. 拖别的文件（`.txt`）→ 只提示，草稿不动，同样没有灰底。
3. 把文件拖到右边的宿主对话区再拖回来 → 宿主那边照常显示自己的遮罩（那是它的正常行为），
   一进入工作台范围就消失。

已在真机复核（Windows 桌面端）：把一个桌面上的 `.html` 拖进「自定义」窗格能被识别并预览，
全程不再出现宿主那层整窗遮罩。
