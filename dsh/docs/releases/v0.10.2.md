# v0.10.2 — 编辑器行号栏的 git 改动标记

> 2026-10-19 · 增量版本 · 自测 host **171** + client **555** 全通过

## 一句话

上一版我说「行内 gutter 做不了」——**说错了**。插件自己有读写文件的通道，也有自己的编辑器，
不需要宿主的编辑器 API。这一版把行号栏补上了。

## 加了什么

打开文件切到「编辑」视图，左边多一列行号；行号左侧的竖条就是相对 HEAD 的改动：

| 竖条 | 含义 |
|---|---|
| 绿色整条 | 新增行 |
| 琥珀整条 | 修改行 |
| 红色短条（贴行顶） | 在这里删过内容，锚点是「原本的下一行」 |
| 无 | 跟 HEAD 一致 |

标题栏同时给一个 `+n ~n −n` 的统计。判定基准是 **HEAD**，已暂存 + 未暂存合在一起算 ——
想知道「暂存区和工作区的区别」去源代码管理的 diff 面板；行号栏只回答
「这个文件相对上次提交，改在哪儿」。

保存后自动重算一次。

## 技术选择

### 只传行号，不传 diff

host 新增 `op: 'linemap'`：

```js
git diff -U0 --no-color --no-ext-diff HEAD -- <file>
```

只解析 `@@` hunk 头，把「新文件的行区间」翻译成标记：

| hunk 形态 | 判定 | 标记 |
|---|---|---|
| `@@ -a,0 +c,d @@` | 原文件这段是空的 | 第 c..c+d-1 行 `add` |
| `@@ -a,b +c,d @@`（b>0, d>0） | 替换 | 第 c..c+d-1 行 `mod` |
| `@@ -a,b +c,0 @@` | 纯删除 | 锚在第 c 行 `del` |

响应是 `{ marks: [{line, kind}], adds, mods, dels }`，几千行的文件也就几百字节。
前端不用解析 patch，也不用为渲染 diff 付出任何代价。

### `-U0` 比「整块标黄」准

`-U0` 拿的是最小 hunk。在中间插两行，只会标那两行；把上下文一起染成改动色是 `-U3` 的行为。

### 行高必须锁死

行号栏和 `<textarea>` 共用 `line-height: 18px`（原来是 `1.65`）。相对值会因像素取整
逐行累积误差，滚到几百行就能看出偏。这条是这一版唯一的「样式即正确性」的地方。

### 其它边界

| 情况 | 行为 |
|---|---|
| 文件不在任何仓库里 | `markState: 'idle'`，行号栏不染色，不报错 |
| 文件在仓库里但被忽略 / 在仓库之外 | 同上（`outside: true`） |
| 未跟踪的新文件 | 整份算新增 |
| 空仓库还没有 HEAD | 整份算新增（`unborn: true`） |
| 超过 8000 行 | 不画行号栏 —— 几万个 DOM 节点比没有标记更糟 |
| 只读预览（大文件截断） | 行号栏照常显示，但不可编辑 |

## 顺手修正的一个 bug

`tmpdir()` 在 Windows 上返回 8.3 短名（`C:\Users\JINSHU~1\...`），而 `git rev-parse --show-toplevel`
返回长路径。两边的 `path.relative` 会算出满屏 `../`，于是文件被误判成「在仓库之外」、标记永远为空。
现在两边都先过一遍 `realpathSync.native` 再比。

## 升级方式

```powershell
& "<你的 DSH 安装目录>\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop add "https://github.com/nscn6fdx44-crypto/dsh-worktable/releases/download/v0.10.2/trae-usage-worktable-0.10.2.tgz"
```

装完**完整退出 DSH 再启动**（`linemap` 是 host 侧新 op，不重启会返回「未知 op」）。
