fix(dsh): 0.8.5 —— 删除其实成功了却报失败；盘符根只能读不能写不能删

一、删除「用不了」的真实根因（本机实测复现）

  probe 里对一个临时文件调 /fs/delete，返回 500：
    {"error":"删除失败：#< CLIXML <Objs Version=… Preparing modules for first use."}
  但 existsSync 已经是 false —— 文件**确实进了回收站**。

  即：Windows 回收站调用成功时，系统命令宿主仍可能返回退出码 1，并把
  「Preparing modules for first use.」这类进度记录按 CLIXML 序列化进 stderr。
  旧代码 `if (code === 0) ok else fail`，于是把成功判成失败，还把整段
  CLIXML 当错误文案糊到 toast 上。用户看到的就是「删除用不了」。

  修法：
  - 成败**以磁盘为准**：等子进程结束后看目标还在不在（成功非 0 / 失败 0 都覆盖）；
  - stderr 只取 <S S="Error">…</S> 里的真错误，纯进度 CLIXML 直接洗成空；
  - 脚本加 $ProgressPreference = "SilentlyContinue"，从源头少写脏东西；
  - **抽干 stdout**（spawn 默认 pipe，写满 64KB 会把子进程卡死，Promise 永不 resolve）；
  - 12s 超时 + kill，不再让前端干等 20s 后报「请求超时」；
  - 每次删除追加一行到 ~/.dsh/worktable-delete.log（时间|ok/fail|耗时|退出码|路径|错误）。

二、盘符根为什么不行 → 权限改成分三档

  原来所有路径（连 list/read）都过白名单根（cwd / home / DSH_HOME / 项目根），
  盘符根不在里面，于是从项目一路 ↑ 到 D:\ 就是 403，删除更是到不了底。
  现在：
  - 读（list / read / stat / reveal）：不设白名单，能翻到盘符根；只挡凭证目录
    （.ssh / .aws / .gnupg / .kube / .dsh / .netrc / .git-credentials）；
  - 写（write / mkdir / rename）：仍只允许白名单内，/fs/list 新增 writable 字段，
    面板据此把「＋ 新建」「✎ 重命名」置灰、状态栏标「只读」；
  - 删：不要求白名单（回收站本身可撤销），但拒绝磁盘根、系统目录
    （%SystemRoot% / Program Files / ProgramData）、白名单根本身、
    白名单根的祖先（删了它等于连工作区一起端掉）。

三、顺手修的两处

  - **删软链接会删掉目标**：原来走 assertExisting → realpathSync 跟随了末段，
    右击链接会把链接指向的东西删掉、链接自己留着。新增 deleteTarget()：
    只 realpath 父目录、末段原样保留、用 lstat 判存在（断链也能删）。
  - 右键菜单改由 store 驱动（store.fs.menu），和侧边栏项目菜单一致；
    菜单打开时先问 /fs/deletable，不能删的项置灰并把原因写在菜单底部
    ——「盘符根为什么不行」现在直接在菜单里回答，不用点了才报错。

测试：73 + 130 全绿（新增盘符根可读/不可删、白名单根祖先、deletable、
writable 标记；客户端新增右键→移到回收站、置灰项点了不发请求）。
